01 / The question

One action.
Different relational
consequences.

Reasoning about physical actions requires determining not only which spatial relations are altered, but fundamentally which premises remain valid across state transitions. Standard vision-language models lack persistent, state-aware representations; consequently, stateless visual re-assessment often allows invalid historical observations to propagate into downstream predictions. We introduce RAVEL, a training-free framework that formalizes dynamic relational reasoning over a persistent, executable spatial world state. RAVEL explicitly tracks evidence validity alongside deterministic geometric propagation: spatial attributes under defined kinematics are resolved analytically, contextual relations outside the action scope are preserved, and a frozen vision-language model is queried selectively only for unresolved states. Evaluated on a 12,000-question diagnostic benchmark spanning observed updates, occluded outcomes, and multi-step trajectories, RAVEL substantially outperforms standard direct inference across diverse foundation models—improving Astra's full-question accuracy from 62.70% to 81.20% and Qwen3-VL-4B from 3.60% to 23.40%, with consistent gains maintained under strictly matched access and query schedules.

1

Model and update

Compile public recipes, actions, and queries into spatial code. Retain or propagate supported attributes, and invalidate current geometry after unsupported motion.

2

Resolve applicable evidence

Compute relations from valid geometry, retain eligible fixed-object evidence, and ask the frozen VLM for fresh judgments. Optional P/L binding makes established findings compulsory.

3

Commit and compose

Validate and commit typed findings with their sources. Combine endpoints and shared participation into change, preservation, and admissible edits; carry the evidence to the next state.

06 / Spatial code

A shared representation.
An executable contract.

The harness compiles public declarations into a persistent spatial representation. A fixed interpreter updates state, checks validity, evaluates supported relations, and composes answers. The frozen model reads code and permitted views to supply unresolved judgments.
